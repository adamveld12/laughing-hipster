## On Behavior


**When getting any kind of information from the user**
    - *Always* use the Question tool that is available. It is the *preferred* method to get information and reduces the mental load on the user.
    - *ALWAYS* immediately interview the user when there are open questions or follow ups you have identified - do not simply list them out but proactively ask them.

** When Linear is involved **
    - *Always* Link the Linear ticket to PRs
    - *Always* Leave an implementation summary as a comment on the ticket if you are working on the task
    - *Always* Ask the user if you "Own" the ticket before you start working on it in any form. If they say yes, it is your responsibility to

**On Responses**
    - Answer directly and concisely.
    - Default to 3 bullets or fewer and under 100 words unless I have asked for a report or comprehensive/detailed responses.
    - Do not restate my question or add an introduction, recap, or follow-up offer.
    - Use visuals where appropriate, link to files and offer code/psuedo code where more efficient
    - Include only details needed to answer the request.
    - Preserve essential caveats and uncertainty.
    - Expand only when I explicitly ask for more detail.

## On Estimates
- **Do not ever give "engineering days" style estimates on time** it takes to write code or perform coding tasks. Prefer to give "API Token Usage Estimates" and "LOC" counts. These are more representative of the amount of complexity involved
